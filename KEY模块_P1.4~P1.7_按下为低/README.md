# KEY模块_P1.4~P1.7_按下为低

独立按键扫描模块（薄模块）：对外只暴露一个 `Key()`，把 P1.4~P1.7 四个引脚的电平翻译成键号 0~4。无初始化、无定时器、无中断；换引脚只改 4 行 `#define`。消抖、边沿检测、长短按这些"业务策略"刻意不内置，但每一条都给出标准升级路径（见扩展路线）。

> 配套文章：[51单片机独立按键扫描_P1.4~P1.7电平采样模块的设计与实现（CSDN）](https://blog.csdn.net/2503_93333717/article/details/170598453)

## 模块信息

| 项目 | 说明 |
|------|------|
| 对外接口 | `unsigned char Key(void)` —— 扫一次按键：返回键号 1~4，无键按下返回 0 |
| 占用引脚 | **P1.4 ~ P1.7**（DIP40 第 5~8 脚） |
| 占用片上资源 | 无定时器 / 无中断 / 约 1B RAM（加边沿检测再 +1B `static`） |
| 依赖 | 无（仅 `REGX51.H`） |
| 初始化 | **不需要**：P1 口上电即为准双向输入态（内部弱上拉），无任何寄存器配置 |

配套模块：[Delay模块_Timer1节拍驱动_差值毫秒延时](../Delay模块_Timer1节拍驱动_差值毫秒延时/README.md) —— 其 `DelayMs(20)` 可用于消抖；不引入该依赖也能工作（见扩展路线 4.1 的代价说明与 4.3 非阻塞方案）。

## 一、接线与键值约定

### 1.1 接线

四个独立按键分别接在 **P1.4 ~ P1.7**（DIP40 封装的第 5~8 脚），每个按键**一端接 I/O，另一端接 GND**：

```text
VCC ──[芯片内部弱上拉]── P1.4 ──┐
                                ├── KEY1 ──┐
GND ────────────────────────────┴──────────┘
（KEY2~KEY4 同理，依次接 P1.5 / P1.6 / P1.7）
```

- 按下：I/O 被直接拉到 GND，读到 **0**；
- 松开：P1 口是准双向口、内部自带弱上拉，读到 **1**。

所以本模块的约定是"**低电平 = 按下**"，目录名里的"按下为低"说的就是这件事。

**一个重要福利**：STC89C52 / AT89S52 的 P1 口内部带弱上拉，按键**不需要外接上拉电阻**，直接"一端接 I/O、一端接 GND"就能可靠读到高低电平。但注意两点：

1. **P0 口是开漏输出，没有内部上拉**，想拿 P0 当按键输入必须外接 4.7k~10k 上拉排阻，别踩这个坑；
2. 走线较长、现场干扰较大时，即使 P1 口也建议外接上拉提高抗干扰能力。

另外这两款芯片上 P1.0 / P1.1 复用 Timer2 的 T2 / T2EX 功能，如果工程里用了 Timer2 要避开 —— 本模块选 P1.4~P1.7 正好没有这个顾虑。

### 1.2 键值约定

`Key()` 每被调用一次，就"扫"一遍四个引脚，返回值约定如下：

| 返回值 | 含义 |
|--------|------|
| `0` | 无键按下 |
| `1` | KEY1（P1.4）按下，源码注释标注原始用途：L 上移 |
| `2` | KEY2（P1.5）按下：L 下移 |
| `3` | KEY3（P1.6）按下：R 上移 |
| `4` | KEY4（P1.7）按下：R 下移 |

> 源码注释里的原始用途是"左右两组四向控制"（点阵屏 / 小游戏类应用）。键名和业务的对应关系完全由应用层自己解释，模块本身不关心 —— 这正是通用模板该有的样子。

## 二、源码解析

### KEY.h（全文）

```c
#ifndef __KEY_H__
#define __KEY_H__

unsigned char Key(void);    /* 扫一次按键：返回键号1~4，无键按下返回0 */

#endif
```

标准的 include guard + 一行函数声明，没有多余的东西。

### KEY.c（全文）

```c
#include "KEY.h"
#include <REGX51.H>

/* 图1：P1.4~P1.7 依次接 K1(L上移)/K2(L下移)/K3(R上移)/K4(R下移)，低电平=按下 */

#define KEY1 P1_4
#define KEY2 P1_5
#define KEY3 P1_6
#define KEY4 P1_7

unsigned char Key(void)
{
    unsigned char KeyNum = 0;
    if (KEY1 == 0) KeyNum = 1;
    if (KEY2 == 0) KeyNum = 2;
    if (KEY3 == 0) KeyNum = 3;
    if (KEY4 == 0) KeyNum = 4;
    return KeyNum;      /* 多键同按时取最后扫描到的键 */
}
```

去掉注释和 include，**有效代码只有 5 行**：初始化 `KeyNum = 0`、四个 `if`、一个 `return`。有三个设计点值得展开讲。

**① 硬件绑定点收敛在 4 行 `#define`。** 这四行是整个文件里唯一出现具体引脚的地方。想换引脚？只改这里，下面的 `if` 一个字都不动。`P1_4` 这种符号是 `REGX51.H` 里现成的 `sbit` 位定义；如果你的头文件没有这个别名，自己补一行 `sbit KEY1 = P1^4;` 即可。

**② 多键同按时，优先级是 KEY4 > KEY3 > KEY2 > KEY1。** 四个 `if` 是顺序执行的、后者覆盖前者：如果 KEY1 和 KEY4 同时按下，KEY1 先把 `KeyNum` 置 1，随后 KEY4 又把它覆盖成 4，最终返回 4。这个行为是**确定**的，但你要心里有数。想改成 KEY1 优先，把顺序 `if` 改成 `if / else if` 就行（见移植指南步骤 5），`else if` 版本还有个附带好处：一旦命中就不再判断后续引脚，指令数更少。

**③ 为什么不内置消抖？这是刻意的设计。** 机械按键触点在按下/松开瞬间会抖动几毫秒到几十毫秒，裸扫描直接用一定会遇到"一按跳好几格"。但这个模块**只负责"把引脚状态翻译成键号"这一件事**：消抖时长取多少、要不要等松手、短按长按的阈值是多少，这些都是**业务决定**的，塞进模块里反而把它焊死在某个业务场景上。所以模块保持裸扫描，消抖方案在扩展路线 4.1 给出，按需取用。

## 三、移植指南（怎么修改一下就能套用）

### 步骤 1：拷文件

把 `KEY.c/.h` 拖进你的 Keil C51 工程，加一下 Include Paths（`Options for Target → C51 → Include Paths`），**完事**。它不需要任何初始化函数、不占定时器、不开中断。

### 步骤 2：换引脚 —— 只改 4 行 `#define`

这是本模块**唯一的硬件绑定点**。比如想改接 P3.2~P3.5：

```c
#define KEY1 P3_2
#define KEY2 P3_3
#define KEY3 P3_4
#define KEY4 P3_5
```

（注意 P3.2/P3.3 是 INT0/INT1 的复用脚，确认你的工程没用外部中断再选它们。）

下面的 4 个 `if` **一个字都不用改**。若目标引脚在寄存器头文件里没有现成的 `sbit` 别名，自己补一行即可：

```c
sbit KEY1 = P3^2;       /* 格式：sbit 名字 = 端口^位号 */
```

**选脚提示**：

- 优先用 P1 / P2 / P3 口，它们都是准双向口、内部带弱上拉；
- **P0 口是开漏输出，必须外接 4.7k~10k 上拉排阻**才能当按键输入用；
- P3.4 / P3.5 是 T0 / T1 的计数输入脚，但**定时器工作在"定时模式"时不占用这两个引脚**，仍可当普通 I/O 用；
- P1.0 / P1.1 在 89 系列上复用 Timer2 的 T2 / T2EX，工程里用了 Timer2 就要避开。

> ⚠️ **换到 STC12 / STC15 / STC8 系列要注意**：这些芯片的 I/O 有四种工作模式，由 `P1M0 / P1M1` 之类的寄存器决定。上电默认是准双向口（弱上拉），通常可以直接用；但如果你的工程把端口改成了推挽输出，按键就读不到低电平了。本模块针对的是 89 系列，没有端口模式寄存器，无需任何初始化。

### 步骤 3：换电平 —— "按下为高"只改比较值

若你的电路是按键接 VCC（按下读 1、松开靠下拉电阻读 0），把 4 个 `== 0` 改成 `== 1`：

```c
if (KEY1 == 1) KeyNum = 1;
...
```

顺手把目录名和注释里的"按下为低"改成"按下为高"，保持仓库命名规则的一致性。

### 步骤 4：换按键数量

- **减少**（只用 2 个键）：删掉多余的 `#define` 和对应 `if` 即可，返回值范围随之缩小；
- **增加**（8 个键）：照样加 `#define KEY5 ...` 和 `if` 分支。注意返回值类型 `unsigned char` 上限 255，够用；
- **超过 8 键**：别再用"一脚一键"的堆法，改矩阵扫描，见扩展路线 4.5。

### 步骤 5：换多键优先级

当前是 KEY4 优先。想让 KEY1 优先，把顺序 `if` 改成 `if / else if`，命中即返回：

```c
if      (KEY1 == 0) KeyNum = 1;
else if (KEY2 == 0) KeyNum = 2;
else if (KEY3 == 0) KeyNum = 3;
else if (KEY4 == 0) KeyNum = 4;
```

`else if` 版本还有个附带好处：一旦命中就不再判断后续引脚，指令数更少。

## 四、扩展路线（改哪里能得到什么）

每一节给出"改哪里 → 得到什么"。

### 4.1 加消抖（最常用的第一个升级）

机械按键抖动几 ms 到几十 ms，裸扫描会把一次按键读成好几次。最简单的做法是**在应用层**"延时 + 复查"（`DelayMs` 来自 [Delay 模块](../Delay模块_Timer1节拍驱动_差值毫秒延时/README.md)）：

```c
unsigned char key = Key();
if (key != 0)
{
    DelayMs(20);            // 跨过抖动窗口
    if (Key() == key)       // 复查：20ms 后仍是同一个键才算真按下
    {
        // 这里写你的业务：切模式、调参数…
        while (Key() != 0); // 等松手，避免一次按下被重复计数
        DelayMs(20);        // 松手也抖，同样消抖一次
    }
}
```

想封进模块里，就把 `KEY.c` 改成自包含版本（需 `#include "Delay.h"`）：

```c
#include "KEY.h"
#include "Delay.h"
#include <REGX51.H>

/* ... 4 行 #define 不变 ... */

unsigned char Key(void)          /* 已消抖：无键返回 0 */
{
    unsigned char KeyNum = 0;

    if (KEY1 == 0) KeyNum = 1;
    if (KEY2 == 0) KeyNum = 2;
    if (KEY3 == 0) KeyNum = 3;
    if (KEY4 == 0) KeyNum = 4;

    if (KeyNum != 0)
    {
        DelayMs(20);             // 消抖
        switch (KeyNum)          // 复查：确认仍是同一个键
        {
            case 1: if (KEY1 != 0) KeyNum = 0; break;
            case 2: if (KEY2 != 0) KeyNum = 0; break;
            case 3: if (KEY3 != 0) KeyNum = 0; break;
            case 4: if (KEY4 != 0) KeyNum = 0; break;
        }
    }
    return KeyNum;
}
```

**代价要清楚**：这么改之后 `Key()` 内部会阻塞 20ms，且 KEY 模块从此**依赖 Delay 模块**（进而依赖 Timer1）。如果不想引入这个依赖，请用 4.3 的非阻塞方案。

### 4.2 边沿检测：按一下只触发一次

4.1 的阻塞消抖解决了抖动，但没解决"按住不放会连续触发"。菜单"下一项"、游戏"上移一格"这类操作只希望在**按下那一刻**触发一次。加一个 `static` 变量记住上次状态即可：

```c
/* KEY.h 追加 */
unsigned char KeyPress(void);    /* 仅在"松开→按下"跳变时返回键号，其余时候返回 0 */

/* KEY.c 追加 */
unsigned char KeyPress(void)
{
    static unsigned char last = 0;   /* static：函数退出后保留，这是边沿检测的关键 */
    unsigned char now = Key();       /* 复用已消抖的 Key() */

    if (now != 0 && last == 0) {     /* 上一轮无键、这一轮有键 = 按下瞬间 */
        last = now;
        return now;
    }
    if (now == 0) last = 0;          /* 松手后复位，才允许下一次触发 */
    return 0;
}
```

应用层就能写成最舒服的样子，不用再手动等松手：

```c
while (1)
{
    unsigned char key = KeyPress();
    if (key == 1) { /* 上移一格，按住也只执行一次 */ }
}
```

> 关键点是 `static` 局部变量存放在 RAM 中、**不会在每次调用时清零**，所以它能记住"上一轮状态"。写成普通局部变量，每轮都被重置为 0，边沿检测就失效了。

### 4.3 非阻塞定时扫描（主循环不卡）

阻塞消抖会让主循环每按一次键就停 20ms，数码管会闪、串口可能丢数据。产品级的做法是**定时采样 + 两次一致**，全程不用任何阻塞延时（需要毫秒节拍源 `Timer1_GetTick()`，接口要求见 [Delay README](../Delay模块_Timer1节拍驱动_差值毫秒延时/README.md)）：

```c
unsigned int tKey = Timer1_GetTick();
unsigned char keyLast = 0, keyStable = 0;

while (1)
{
    if ((unsigned int)(Timer1_GetTick() - tKey) >= 10)   /* 每 10ms 扫一次 */
    {
        tKey = Timer1_GetTick();
        if (Key() == keyLast) keyStable = keyLast;   /* 连续两次一致才算稳 */
        keyLast = Key();

        if (keyStable != 0) { /* 处理按键，立刻返回，不阻塞 */ }
    }

    /* 这里可以刷数码管、跑串口、算业务 —— 完全不被按键拖住 */
}
```

若已按 Delay README 的扩展路线给 `Delay.c` 加了 `DelayCheck()`，条件可直接写成 `if (DelayCheck(tKey, 10))`，更直观。这套"定时采样 + 两次一致"的消抖不用任何阻塞延时，是产品级按键处理的标准写法。

### 4.4 短按 / 长按判定（复用 Delay 的差值法）

按下时记一个时间戳，松手时算差值，就能区分短按和长按（"差值 + 回绕"原理详见 [Delay README 第二节](../Delay模块_Timer1节拍驱动_差值毫秒延时/README.md)）：

```c
#include "Timer1.h"

#define LONG_PRESS_MS  1000

/* 返回：0=无动作，1=短按，2=长按。需在主循环中持续调用 */
unsigned char KeyJudge(unsigned char key)
{
    static unsigned int pressTick = 0;

    if (key != 0 && pressTick == 0)
        pressTick = Timer1_GetTick();          /* 记下按下时刻 */

    if (key == 0 && pressTick != 0)            /* 松手了，结算时长 */
    {
        unsigned int held = Timer1_GetTick() - pressTick;   /* 差值法，回绕也正确 */
        pressTick = 0;
        return (held >= LONG_PRESS_MS) ? 2 : 1;
    }
    return 0;
}
```

想做"按住超过 1 秒立刻触发、不必等松手"，把结算条件从"松手"改成 `held >= LONG_PRESS_MS` 即可。改 `LONG_PRESS_MS` 一个宏就能调整长按阈值。

### 4.5 扩成 4x4 矩阵键盘（16 键仍只占 8 脚）

独立按键"一脚一键"，16 个键就要 16 个 I/O，51 根本不够用。矩阵扫描把引脚需求降到"行数 + 列数"：

```c
/* 行：P1.0~P1.3 输出低电平；列：P1.4~P1.7 输入（内部弱上拉） */
unsigned char KeyMatrix(void)
{
    unsigned char row, col, key = 0;

    for (row = 0; row < 4; row++)
    {
        /* 低 4 位=行线，只把第 row 行拉低；高 4 位=列线，全置 1 作输入 */
        P1 = 0xF0 | (unsigned char)~(0x01 << row);

        for (col = 0; col < 4; col++)
            /* 该列被按下的键拉到低电平 → 命中 (row, col) 交叉点 */
            if (((P1 >> 4) & (0x01 << col)) == 0)
                key = row * 4 + col + 1;          /* 键号 1~16 */
    }
    P1 |= 0x0F;                              /* 恢复行线为高，不影响下次扫描 */
    return key;
}
```

改动要点：4 行 `#define` 换成行 / 列两组引脚定义，扫描逻辑从"4 个 if"换成"双重 for"，键号编码从 1~4 变成 1~16。**消抖、边沿检测、长短按三套扩展可以原样沿用**，因为它们的输入都只是"一个键号"。

### 4.6 返回位掩码，支持多键同按

当前的"后者覆盖前者"只能报告一个键。要同时识别多个键（游戏里的"斜向移动"、组合快捷键），把返回值改成位掩码：

```c
unsigned char KeyBits(void)
{
    unsigned char bits = 0;
    if (KEY1 == 0) bits |= 0x01;
    if (KEY2 == 0) bits |= 0x02;
    if (KEY3 == 0) bits |= 0x04;
    if (KEY4 == 0) bits |= 0x08;
    return bits;      /* 例：0x05 = KEY1 与 KEY3 同时按下 */
}
```

应用层用 `if (bits & 0x01)` 逐位判断即可。

### 4.7 接中断，做到"零轮询"

按键也可以不轮询：把 KEY1 接到 **P3.2（INT0，DIP40 第 12 脚）** 或 **P3.3（INT1，第 13 脚）**，开 `EX0 / EA`，在 `void INT0_ISR(void) interrupt 0` 里置一个 `keyFlag`，主循环见标志再扫描确认。好处是空闲时 CPU 可以进 `PCON |= 0x01`（Idle 模式）省电，按键来了才被唤醒。代价是要处理"中断里不能消抖"的问题 —— 通常做法是 ISR 只置标志，消抖仍放主循环。

## 五、资源占用

| 资源 | 占用情况 |
|------|----------|
| I/O | **P1.4~P1.7** 共 4 个（DIP40 第 5~8 脚），一端接 I/O 一端接 GND，**按下读 0** |
| 定时器 | **不占用** |
| 中断 | **不占用**（走 4.7 中断式按键则另需 EX0/EX1 + EA） |
| RAM | 约 1 B（局部变量 `KeyNum`）+ 1 B（若用 4.2 边沿检测的 `static last`） |
| ROM / Flash | 极小（本体约十余条指令；加消抖 / 边沿检测后仍在几十字节量级） |
| 特殊功能寄存器 | P1（地址 0x90，只读位，位寻址 0x94~0x97）—— **不写 P1，不干扰同口其他位** |

与 [Delay 模块](../Delay模块_Timer1节拍驱动_差值毫秒延时/README.md) 同时使用：4 个 I/O + Timer1 + ET1/EA + 约 6B RAM，无任何资源竞争。

## 六、使用边界（用之前必须知道的四件事）

1. **当前版本不含消抖**：`Key()` 是纯电平采样，机械按键直接使用会读到抖动造成的重复键值。请务必配合 4.1（阻塞式）或 4.3（非阻塞式）处理。
2. **当前版本不含松手检测**：按住不放时，每调用一次 `Key()` 都会返回同一个键号，业务会被重复触发。需要"一次按下只响应一次"时，加边沿检测（4.2）或在应用层 `while (Key() != 0);` 等松手。
3. **多键同按只报告一个**：优先级固定为 KEY4 > KEY3 > KEY2 > KEY1。需要真正识别组合键请改用位掩码（4.6）。
4. **依赖寄存器头文件中的 sbit 别名**：`P1_4` 等符号由 `<REGX51.H>` 提供。换用没有该别名的头文件（如某些 STC 官方头文件）时，需自行 `sbit KEY1 = P1^4;` 补定义。

> **关于消抖引入的模块依赖**：一旦把 `DelayMs()` 写进 `KEY.c`，KEY 模块就依赖 Delay → 依赖 Timer1，且 `Key()` 变为阻塞 20ms。想保持 KEY 的零依赖特性，请用 4.3 的非阻塞扫描方案。
