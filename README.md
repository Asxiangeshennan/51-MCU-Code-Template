# 51-MCU-Code-Template

这是一个用来存放 **51 单片机（STC89C52 / AT89S52 等 8051 内核）** 代码模板的仓库。

所有模板都遵循同一个目标：**把"能跑就行"的代码，拆成"换个工程就能直接套用"的模块**。

本文档讲清四件事：

1. **模块化编程**的分层思路，以及"薄模块"和"厚模块"两种典型形态；
2. **改哪里就能套用** —— 每个模块的硬件绑定点收敛在哪几行；
3. **改哪里就能长出新功能** —— 逐条给出"改动 → 效果"的扩展路线；
4. **占用了哪些引脚和片上资源** —— 一张总表说清，避免新工程里撞车。

## 一、模块化编程思想

### 1. 三层分工

| 层次 | 职责 | 本仓库示例 |
|------|------|-----------|
| 应用层 | 业务逻辑（点灯、菜单、游戏控制…） | `main.c`（由使用者自建） |
| 驱动 / 服务层 | 把硬件能力封装成纯软件接口 | `Delay.c`：`DelayMs(500)`<br>`KEY.c`：`Key()` → 键号 |
| 硬件配置层 | 寄存器级初始化与中断服务 | 你的 `Timer1.c`：`Timer1_Init()` + ISR |

模块之间**只通过 .h 中声明的函数通信**，绝不跨模块直接读写寄存器或共享全局变量。

### 2. 接口最小化

两个头文件加起来只有两行函数声明：

```c
void          DelayMs(unsigned int ms);   /* Delay.h：阻塞延时约 ms 毫秒 */
unsigned char Key(void);                  /* KEY.h：扫一次按键，返回 0~4 */
```

调用者不需要知道节拍从哪来、误差多大、按键接在哪个引脚、是高有效还是低有效 —— 这正是"可套用"的前提：
**接口越窄，被替换 / 升级时波及的代码越少。**

### 3. 单向依赖

```text
                      ┌──> Delay（服务层）──> Timer1（硬件层）
应用层 main.c ────────┤        不回调            不认识 Delay
                      └──> KEY（服务层）───> P1.4~P1.7（直接寄存器）
                               不认识 Delay，也不认识 main
```

下层永远不知道上层的存在。因此 `Timer1` 可以同时喂给 Delay、按键消抖、PWM、串口超时等任意多个模块；
`KEY` 也可以被任意业务调用，且**删掉 Delay 模块，KEY 照常工作**（只是失去消抖手段）。

### 4. 两种典型形态：厚模块 vs 薄模块

| | **Delay**（厚模块） | **KEY**（薄模块） |
|---|---|---|
| 是否依赖其他模块 | 是，依赖 Timer1 节拍 | 否，自给自足 |
| 是否操作寄存器 | **完全不操作**（纯算法） | 直接读 `P1_4~P1_7` |
| 硬件绑定点 | 收敛在 `Timer1_GetTick()` 这一个函数名 | 收敛在顶部 4 行 `#define` |
| 分层是否完整 | 服务层 / 硬件层严格分离 | 两层合并（模块太薄，分开反而累赘） |

**这里有一条值得记住的权衡**：`KEY.c` 同时扮演了服务层和硬件层，按纯粹的分层原则它应该再拆一层
（例如 `GPIO_ReadPort1()`）。但对于只有十几行、没有初始化、没有状态的模块，**强行拆层只会增加文件数量，
不会增加可维护性**。判断标准是：*硬件绑定点是否收敛在一处、是否能一眼改完*。`KEY.c` 把 4 个引脚写在连续的
4 行 `#define` 里、寄存器头文件写在第 2 行 `#include`，改起来一目了然 —— 这就够了。

模块变厚（要加消抖、加边沿检测、加矩阵扫描）时，再把引脚读写下沉到独立的 GPIO 层也不迟。

### 5. 一个典型用法：两模块组合

```c
#include <REGX52.H>
#include "Timer1.h"
#include "Delay.h"
#include "KEY.h"

sbit LED = P2^0;

void main()
{
    unsigned char key;

    Timer1_Init();          // 必须先启动节拍源，否则 DelayMs 永不返回
    while (1)
    {
        key = Key();        // 扫一次按键：0=无键，1~4=键号
        if (key != 0)
        {
            DelayMs(20);    // 消抖：跨过机械触点的抖动窗口
            if (Key() == key)   // 复查：20ms 后仍是同一个键才算真按下
            {
                LED = ~LED;         // 这里换成你的业务：切模式、调参数…
                while (Key() != 0); // 等松手，避免一次按下被重复计数
                DelayMs(20);        // 松手也抖，同样消抖一次
            }
        }
    }
}
```

> 这段代码演示的是**最朴素的阻塞式按键处理**，胜在直观。它会占用 CPU（`while(Key()!=0)` 期间主循环停摆），
> 若主循环还要刷数码管 / 跑串口，请改用非阻塞扫描，见 [2.3-1](#231-非阻塞软定时器最值得做的升级) 与 [3.3-4](#334-非阻塞定时扫描主循环不卡)。

## 二、Delay 模块详解

### 2.1 差值法：3 行核心代码为什么"回绕也不怕"

`Delay.c` 的全部核心逻辑：

```c
void DelayMs(unsigned int ms)
{
    unsigned int start = Timer1_GetTick();
    while ((unsigned int)(Timer1_GetTick() - start) < ms)
        ;
}
```

其中藏着本模块最核心的设计：**为什么比较"流逝差值"，而不是比较"当前时刻 ≥ 目标时刻"？**

#### 1. 绝对时刻比较的经典事故

`tick` 是 `unsigned int`，每 65.536 s 回绕归零。直觉写法是"先算目标时刻，再死等"：

```c
unsigned int start  = Timer1_GetTick();
unsigned int target = start + ms;        /* 例：start=65530, ms=10 → 65540 溢出截断成 4 */
while (Timer1_GetTick() < target)        /* 入口时 tick=65530，65530 < 4 不成立 */
    ;
```

只要目标时刻跨过回绕点，`start + ms` 就被截断成一个"很小"的数，循环**第一次判断就为假 —— 延时直接消失**。
这不是小概率 bug：程序每跑 65.5 秒，tick 必然回绕一圈。

#### 2. 差值法为什么天然免疫

C 标准规定：**无符号整数运算永远按模 2^N 进行**（不存在"溢出"这个概念）。
所以只要两次读 tick 之间的真实流逝时间小于 65536 ms，`now - start` 的模运算结果就**恒等于**真实流逝的毫秒数 —— 与 tick 转了几圈无关。

拿上面的事故现场重演一遍（`start = 65530`，`ms = 10`）：

| 事件 | tick 实际值 | `now - start`（模 65536） | 真实流逝 |
|------|------------|--------------------------|---------|
| 读取 start | 65530 | 0 | 0 ms |
| 5 ms 后 | 65535 | 5 | 5 ms |
| 6 ms 后 | **0（回绕）** | 6 | 6 ms |
| 10 ms 后 | 4 | **10 ≥ 10，退出** | 10 ms ✅ |

回绕瞬间差值照样平滑爬升，不需要任何特殊分支处理。

两个推论：

- 只要单次延时 ≤ 65535 ms（一个回绕周期内），`now - start` 就在 `[0, 65535]` 内单调递增、不会中途归零 —— 循环既不会提前退出，也不会迟到。这也是 `DelayMs` 参数用 `unsigned int`（上限 65535 ms ≈ 65.5 s）刚刚好的原因；
- 这套"差值 + 回绕"逻辑可原样复制到按键长按判定（见 [3.3-3](#333-短按--长按判定复用-delay-的差值法)）、串口帧超时、心跳掉线检测等一切"流逝时间"场景。

#### 3. 精度账

节拍粒度是 1 ms，`start` 的读取相位随机，所以实际延时落在 `[ms − 1ms, ms + 1ms]` 区间内，**误差不超过一个节拍**。
对比软件空转延时动辄 ±10% 的"开盲盒"（魔法循环常数依赖编译器版本与优化等级，换晶振全作废），这是数量级的提升。

### 2.2 怎么修改一下就能套用（移植指南）

以下假设你新建了一个 Keil C51 工程，想把本模板搬进去。

#### 步骤 1：拷文件、加头文件搜索路径

把 `Delay.c/.h` 与你的 `Timer1.c/.h` 一起拖入工程，并在
`Options for Target → C51 → Include Paths` 里加上它们所在的目录。

#### 步骤 2：对准节拍源 —— 换定时器只需改两处

`Delay.c` 里只有两行与具体定时器绑定：

```c
unsigned int start = Timer1_GetTick();
while ((unsigned int)(Timer1_GetTick() - start) < ms)
```

想改用 **Timer0** 提供节拍？把这两行的 `Timer1_GetTick()` 换成 `Timer0_GetTick()`、
第 2 行的 `#include "Timer1.h"` 换成 `"Timer0.h"` 即可，算法本身一个字都不用动。
这就是"取节拍函数"作为唯一耦合点的价值。

#### 步骤 3：对准晶振 —— 改重装初值

1ms 节拍的初值随晶振变化（模式 1，16 位定时器，机器周期 = 12 / 晶振频率）：

| 晶振 | 计数一次耗时 | 1ms 需要的计数 | 重装初值（THx/TLx） |
|------|-------------|----------------|---------------------|
| 12 MHz | 1 µs | 1000 | `0xFC` / `0x18`（65536−1000 = 64536 = 0xFC18） |
| 11.0592 MHz | ≈1.085 µs | ≈922 | `0xFC` / `0x66`（65536−922 = 64614 = 0xFC66） |

在 `Timer1_Init()` 与 ISR 的重装代码里同步修改这两个字节即可。

#### 步骤 4：对准精度需求 —— 改节拍周期

ISR 里若把重装值改为 65536−50000，节拍就变成 50ms/次；此时只要把 `Delay.c` 中的比较改成：

```c
while ((unsigned int)(Timer1_GetTick() - start) < ms / 50) ;   // 单位换算
```

更推荐的做法：定义 `#define TICK_MS 1`，让换算集中在一处（注意用"tick 数向上取整"的写法，避免小延时被整除截断为 0）：

```c
#define TICK_MS  1                       /* 一个节拍 = 1ms，换晶振/换重装值时只改这里 */
while ((unsigned int)(Timer1_GetTick() - start) < (ms + TICK_MS - 1) / TICK_MS)
    ;
```

#### 步骤 5：对准编译器 —— 关键字差异

| 写法（Keil C51） | SDCC 等价写法 |
|------------------|---------------|
| `sbit / sfr` | `__sbit __at 0xA0` / `__sfr __at 0x80` |
| `code` 数组常量 | `__code` → `__flash`（部分型号） |
| `void main(void)` + `while(1)` | 相同，但 ISR 用 `__interrupt(n)` |

`Delay.c` 不含任何关键字相关的硬件代码，**天然跨编译器**；`KEY.c` 只用了 `sbit` 形式的位定义（来自寄存器头文件），
换编译器时只需替换头文件，扫描逻辑本身同样通用。需要动的永远只有硬件配置层。

#### 步骤 6：裸机直接套用，不必改造

`DelayMs` 是纯阻塞语义，适合流水灯、数码管演示、蜂鸣器节奏这类"时间就是业务"的场景，
拷过去就能用，无需操作系统或调度器。

### 2.3 修改一下能实现什么不一样的功能（扩展路线）

每一节给出"改哪里 → 得到什么"。

#### 2.3.1 非阻塞软定时器（最值得做的升级）

把"死等"改成"到期判断"，新增一个函数即可：

```c
/* Delay.h 追加 */
unsigned char DelayCheck(unsigned int start, unsigned int ms);
/* Delay.c 追加：到期返回 1；利用回绕差值，天然支持溢出 */
unsigned char DelayCheck(unsigned int start, unsigned int ms)
{
    return (unsigned int)(Timer1_GetTick() - start) >= ms;
}
```

应用层写法（注意 `t` 必须在主循环**外层**初始化一次，否则每圈都重置、永远不到期）：

```c
unsigned int t = Timer1_GetTick();     // 循环外初始化
while (1)
{
    if (DelayCheck(t, 500)) {
        P2 ^= 0x01;                    // 每 500ms 翻转 LED
        t = Timer1_GetTick();          // 重新计时
    }
    // 这 500ms 里 CPU 可以去扫按键、刷新数码管 —— 单核也能"并发"
}
```

#### 2.3.2 微秒级延时

两种改法任选：

- **自动重装法（Timer1 模式 2，推荐）**：把 Timer1 切到 8 位自动重装，12MHz 下初值 `TH1 = TL1 = 256−12 = 0xF4`，每溢出一次恰好 12µs；ISR 里累加的就不再是"毫秒 tick"而是"12µs 计数"，`DelayUs(us)` 照抄差值逻辑、把比较阈值换成 `us / 12` 即可（无需软件重装，抖动更小）；
- **双计数器法**：粗计时用 1ms 节拍、细分段用 TLx 当前值插值，可做几 µs ~ 十几 µs 的精确定时（DS18B20 时序够用）。

> ⚠️ 注意：Timer1 一旦被挪去做 µs 延时，就不能同时当 1ms 节拍源了。
> 两者都要用时，请让 Timer1 专职做节拍、另找 Timer0（或 Timer2）做 µs 延时。

#### 2.3.3 超时退出 / 带喂狗的延时

在 `while` 循环里塞入副作用：

```c
while ((unsigned int)(Timer1_GetTick() - start) < ms)
{
    WDT_Restart();      // STC 系列清看门狗
    // 或在这里轮询串口接收缓冲，防止阻塞期间丢数据
}
```

#### 2.3.4 倒计时显示

`Timer1_GetTick() - start` 本身就是"已流逝毫秒数"，拿出去就是现成的倒计时 / 正计时：

```c
unsigned int elapsed = Timer1_GetTick() - start;   // 送数码管显示剩余 ms
```

#### 2.3.5 把同一套差值法推广到其它场景

差值 + 无符号回绕是个通用模式，可以原样复制成：

- **按键长按判定**：记录按下时刻，`elapsed > 1000` 判为长按（KEY 模块已给出完整实现，见 [3.3-3](#333-短按--长按判定复用-delay-的差值法)）；
- **通讯帧超时**：UART 收到首字节后，`elapsed > 50` 且无新字节则判帧结束；
- **心跳 / 掉线检测**：`now - lastRx > 3000` 视为链路断开。

#### 2.3.6 精度再进一步的两个小改动

1. ISR 中先重装初值再做其它事，并把节拍累加放在重装之后，减少抖动；
2. 若单次定时超过 65535 个计数，改为"溢出次数 × 溢出周期 + TLx 残值"的组合计时（见 [2.3-2](#232-微秒级延时) 双计数器法）。

## 三、KEY 模块详解

### 3.1 实现与键值约定

`KEY.c` 全文（不含注释）只有 5 行有效代码：

```c
#define KEY1 P1_4
#define KEY2 P1_5
#define KEY3 P1_6
#define KEY4 P1_7

unsigned char Key(void)
{
    unsigned char KeyNum = 0;
    if (KEY1 == 0) KeyNum = 1;
    if (KEY2 == 0) KeyNum = 2;
    if (KEY3 == 0) KeyNum = 3;
    if (KEY4 == 0) KeyNum = 4;
    return KeyNum;      /* 多键同按时取最后扫描到的键 */
}
```

**必须先知道的三件事：**

| 约定 | 说明 |
|------|------|
| **电平** | **低电平 = 按下**（按键一端接 I/O，一端接 GND）；松开时读到 1，返回 0 |
| **返回值** | `0` = 无键按下；`1~4` = KEY1~KEY4 |
| **多键同按** | 4 个 `if` 顺序执行、后者覆盖前者，所以**优先级是 KEY4 > KEY3 > KEY2 > KEY1** |

**这个模块目前只做"裸扫描"，不含消抖、不含边沿检测、不含松手等待。**
这是刻意的：模块只负责"把引脚状态翻译成键号"这一件事，其余策略（消抖时长、是否等松手、
短按长按阈值）都是**业务决定**，应由应用层或扩展后的模块提供。直接拿去用会遇到抖动问题，
消抖方案见 [3.3-1](#331-加消抖最常用的第一个升级)。

> 源码注释里标注的原始用途是「P1.4~P1.7 依次接 K1(L上移) / K2(L下移) / K3(R上移) / K4(R下移)」，
> 即左右两组四向控制（点阵屏 / 小游戏类应用）。键名与业务的对应关系完全由应用层自己解释，
> 模块本身不关心 —— 这正是通用模板该有的样子。

### 3.2 怎么修改一下就能套用（移植指南）

#### 步骤 1：拷文件

把 `KEY.c/.h` 拖入工程、加 Include Paths，**完事**。
它不需要任何初始化函数（P1 口上电即为准双向输入态）、不占定时器、不开中断。

#### 步骤 2：换引脚 —— 只改 4 行 #define

这是本模块**唯一的硬件绑定点**。想改接 P3.2~P3.5（外部中断脚，做按键时需确认未复用 INT0/INT1）：

```c
#define KEY1 P3_2
#define KEY2 P3_3
#define KEY3 P3_4
#define KEY4 P3_5
```

下面的 4 个 `if` **一个字都不用改**。若目标引脚在寄存器头文件里没有现成的 `sbit` 别名，自己补一行即可：

```c
sbit KEY1 = P3^2;       /* 格式：sbit 名字 = 端口^位号 */
```

**选脚提示**：优先用 P1 / P2 / P3 口。STC89C52 / AT89S52 的 **P1 口是准双向口、内部带弱上拉**，
按键可直接"一端接 I/O、一端接 GND"而不必外接上拉电阻；**P0 口是开漏输出，必须外接 4.7k~10k 上拉排阻**
才能当按键输入用，别踩这个坑。另外这两款芯片上 P1.0 / P1.1 复用 Timer2 的 T2 / T2EX 功能，
若工程里用了 Timer2 就要避开 —— 本模块选 P1.4~P1.7 正无此顾虑。

> ⚠️ **换到 STC12 / STC15 / STC8 系列要注意**：这些芯片的 I/O 有四种工作模式，由 `P1M0 / P1M1`
> 之类的寄存器决定，上电默认是准双向口（弱上拉），通常可直接用；但若你的工程改过端口模式为
> 推挽输出，按键就读不到低电平了。本模板针对的是 89 系列，**没有端口模式寄存器，无需任何初始化**。

#### 步骤 3：换电平 —— "按下为高"只改比较值

若你的电路是按键接 VCC（按下读 1、松开靠下拉电阻读 0），把 4 个 `== 0` 改成 `== 1`：

```c
if (KEY1 == 1) KeyNum = 1;
...
```

顺手把目录名和注释里的"按下为低"改成"按下为高"，保持仓库命名规则的一致性。

#### 步骤 4：换按键数量

- **减少**（只用 2 个键）：删掉多余的 `#define` 和对应 `if` 即可，返回值范围随之缩小；
- **增加**（8 个键）：照样加 `#define KEY5 ...` 和 `if` 分支。注意返回值类型 `unsigned char` 上限 255，够用；
- **超过 8 键**：别再用"一脚一键"的堆法，改矩阵扫描，见 [3.3-5](#335-扩成-4x4-矩阵键盘16-键仍只占-8-脚)。

#### 步骤 5：换多键优先级

当前是 KEY4 优先。想让 KEY1 优先，把顺序 `if` 改成 `if / else if`，命中即返回：

```c
if      (KEY1 == 0) KeyNum = 1;
else if (KEY2 == 0) KeyNum = 2;
else if (KEY3 == 0) KeyNum = 3;
else if (KEY4 == 0) KeyNum = 4;
```

`else if` 版本还有个附带好处：一旦命中就不再判断后续引脚，指令数更少。

### 3.3 扩展路线：改哪里能得到什么

#### 3.3.1 加消抖（最常用的第一个升级）

机械按键触点在按下 / 松开的瞬间会抖动几毫秒到几十毫秒，裸扫描会把一次按键读成好几次。
最小改动是**在应用层**加"延时 + 复查"（完整例子见 [第一章·5](#5-一个典型用法两模块组合)）：

```c
if (Key() != 0) {
    DelayMs(20);                 // 跨过抖动窗口
    if (Key() == key) { /* 确认 */ }
}
```

想封进模块里，就把 `KEY.c` 改成自包含版本（需 `#include "Delay.h"`）：

```c
#include "KEY.h"
#include "Delay.h"
#include <REGX51.H>

/* ... 4 行 #define 不变 ... */

unsigned char Key(void)          /* 已消抖：无键返回 0 */
{
    unsigned char KeyNum = 0;

    if (KEY1 == 0) KeyNum = 1;
    if (KEY2 == 0) KeyNum = 2;
    if (KEY3 == 0) KeyNum = 3;
    if (KEY4 == 0) KeyNum = 4;

    if (KeyNum != 0)
    {
        DelayMs(20);             // 消抖
        switch (KeyNum)          // 复查：确认仍是同一个键
        {
            case 1: if (KEY1 != 0) KeyNum = 0; break;
            case 2: if (KEY2 != 0) KeyNum = 0; break;
            case 3: if (KEY3 != 0) KeyNum = 0; break;
            case 4: if (KEY4 != 0) KeyNum = 0; break;
        }
    }
    return KeyNum;
}
```

**代价要清楚**：这么改之后 `Key()` 内部会阻塞 20ms，且 KEY 模块从此**依赖 Delay 模块**（进而依赖 Timer1）。
如果不想引入这个依赖，请用 [3.3-4](#334-非阻塞定时扫描主循环不卡) 的非阻塞方案。

#### 3.3.2 边沿检测：按一下只触发一次

阻塞式消抖解决了抖动，但没解决"按住不放会连续触发"。游戏里的"上移一格"、菜单里的"下一项"
通常只希望在**按下那一刻**触发一次。加一个 `static` 变量记住上次状态即可：

```c
/* KEY.h 追加 */
unsigned char KeyPress(void);    /* 仅在"松开→按下"跳变时返回键号，其余时候返回 0 */

/* KEY.c 追加 */
unsigned char KeyPress(void)
{
    static unsigned char last = 0;   /* static：函数退出后保留，这是边沿检测的关键 */
    unsigned char now = Key();       /* 复用已消抖的 Key() */

    if (now != 0 && last == 0) {     /* 上一轮无键、这一轮有键 = 上升沿（按下瞬间） */
        last = now;
        return now;
    }
    if (now == 0) last = 0;          /* 松手后复位，才允许下一次触发 */
    return 0;
}
```

应用层就能写成最舒服的样子，不用再手动等松手：

```c
while (1)
{
    key = KeyPress();
    if (key == 1) { /* 上移一格，按住也只会执行一次 */ }
}
```

> `static` 局部变量存放在 RAM 中且**不会在每次调用时清零**，这是它能记住"上一轮状态"的原因；
> 写成普通局部变量，边沿检测就失效了（每轮都被重置为 0）。

#### 3.3.3 短按 / 长按判定（复用 Delay 的差值法）

这里正是 [2.1](#21-差值法3-行核心代码为什么回绕也不怕) 那套"差值 + 回绕"逻辑的实战应用 ——
按下时记一个时间戳，松手时算差值：

```c
#include "Timer1.h"

#define LONG_PRESS_MS  1000

/* 返回：0=无动作，1=短按，2=长按。需在主循环中持续调用 */
unsigned char KeyJudge(unsigned char key)
{
    static unsigned int pressTick = 0;

    if (key != 0 && pressTick == 0)
        pressTick = Timer1_GetTick();          /* 记下按下时刻 */

    if (key == 0 && pressTick != 0)            /* 松手了，结算时长 */
    {
        unsigned int held = Timer1_GetTick() - pressTick;   /* 差值法，回绕也正确 */
        pressTick = 0;
        return (held >= LONG_PRESS_MS) ? 2 : 1;
    }
    return 0;
}
```

想做"按住超过 1 秒立刻触发、不必等松手"，把结算条件从"松手"改成 `held >= LONG_PRESS_MS` 即可。
改 `LONG_PRESS_MS` 一个宏就能调整长按阈值。

#### 3.3.4 非阻塞定时扫描（主循环不卡）

阻塞消抖会让主循环每按一次键就停 20ms，数码管会闪、串口可能丢数据。
配合 [2.3-1](#231-非阻塞软定时器最值得做的升级) 的 `DelayCheck()`，可以做到"每 10ms 扫一次，中间 CPU 全空出来"：

```c
unsigned int tKey = Timer1_GetTick();
unsigned char keyLast = 0, keyStable = 0;

while (1)
{
    if (DelayCheck(tKey, 10))            /* 每 10ms 扫一次 */
    {
        tKey = Timer1_GetTick();
        if (Key() == keyLast) keyStable = keyLast;   /* 连续两次一致才算稳 */
        keyLast = Key();

        if (keyStable != 0) { /* 处理按键，立刻返回，不阻塞 */ }
    }

    /* 这里可以刷数码管、跑串口、算业务 —— 完全不被按键拖住 */
}
```

这套"定时采样 + 两次一致"的消抖**不用任何 Delay 阻塞**，是产品级按键处理的标准写法。

#### 3.3.5 扩成 4x4 矩阵键盘（16 键仍只占 8 脚）

独立按键"一脚一键"，16 个键就要 16 个 I/O，51 根本不够用。矩阵扫描把引脚需求降到"行数 + 列数"：

```c
/* 行：P1.0~P1.3 输出低电平；列：P1.4~P1.7 输入（内部弱上拉） */
unsigned char KeyMatrix(void)
{
    unsigned char row, col, key = 0;

    for (row = 0; row < 4; row++)
    {
        /* 低 4 位=行线，只把第 row 行拉低；高 4 位=列线，全置 1 作输入 */
        P1 = 0xF0 | (unsigned char)~(0x01 << row);

        for (col = 0; col < 4; col++)
            /* 该列被按下的键拉到低电平 → 命中 (row, col) 交叉点 */
            if (((P1 >> 4) & (0x01 << col)) == 0)
                key = row * 4 + col + 1;          /* 键号 1~16 */
    }
    P1 |= 0x0F;                              /* 恢复行线为高，不影响下次扫描 */
    return key;
}
```

改动要点：4 行 `#define` 换成行 / 列两组引脚定义，扫描逻辑从"4 个 if"换成"双重 for"，
键号编码从 1~4 变成 1~16。**消抖、边沿检测、长短按三套扩展可以原样沿用**，因为它们的输入都只是"一个键号"。

#### 3.3.6 返回位掩码，支持多键同按

当前的"后者覆盖前者"只能报告一个键。要同时识别多个键（游戏里的"斜向移动"、组合快捷键），
把返回值改成位掩码：

```c
unsigned char KeyBits(void)
{
    unsigned char bits = 0;
    if (KEY1 == 0) bits |= 0x01;
    if (KEY2 == 0) bits |= 0x02;
    if (KEY3 == 0) bits |= 0x04;
    if (KEY4 == 0) bits |= 0x08;
    return bits;      /* 例：0x05 = KEY1 与 KEY3 同时按下 */
}
```

应用层用 `if (bits & 0x01)` 逐位判断即可。

#### 3.3.7 接中断，做到"零轮询"

按键也可以不轮询：把 KEY1 接到 **P3.2（INT0，DIP40 第 12 脚）** 或 **P3.3（INT1，第 13 脚）**，
开 `EX0 / EA`，在 `void INT0_ISR(void) interrupt 0` 里置一个 `keyFlag`，主循环见标志再扫描确认。
好处是空闲时 CPU 可以进 `PCON |= 0x01`（Idle 模式）省电，按键来了才被唤醒。
代价是要处理"中断里不能消抖"的问题 —— 通常做法是 ISR 只置标志，消抖仍放主循环。

> Timer0、Timer2、串口以外的全部中断与优先级资源也都还空着。

### 4.4 寄存器速查（Timer1 模式 1）

```text
TMOD &= 0x0F; TMOD |= 0x10;   // T1: 模式1，16位定时（只动高 4 位，不影响 Timer0）
TH1 = 0xFC; TL1 = 0x18;       // 12MHz → 1ms（65536−1000 = 0xFC18）
                              // 11.0592MHz → TH1 = 0xFC, TL1 = 0x66
ET1 = 1; EA = 1;              // 开 T1 中断、总中断
TR1 = 1;                      // 启动
// ISR（中断号 3，向量 0x1B）: TF1 硬件自动清零，先重装 TH1/TL1，再 tick++
```

```text
// KEY 模块无需任何寄存器配置。P1 上电默认为准双向口（弱上拉），
// 直接读 P1_4~P1_7 即可；地址 P1=0x90，位寻址 0x94~0x97。
```

节拍源的三个实现要点：

1. **节拍变量 `tick` 是 16 位，8051 读它需要两条指令**。若读到一半被 ISR 打断，会拼出"新低字节 + 旧高字节"的错值，最坏偏差可达 256 ms 量级。因此 `Timer1_GetTick()` 内部应加一个两条指令长度的短临界区（开销可忽略）：

   ```c
   unsigned int Timer1_GetTick(void)
   {
       unsigned int t;
       EA = 0;      /* 防读撕裂：读完整再开中断 */
       t = tick;
       EA = 1;
       return t;
   }
   ```

2. **模式 1 不会自动重装**，必须在 ISR 里手动补初值，并按"先重装、后累加"的顺序写，减小节拍抖动；
3. **ISR 必须短**：只做"重装 + 自增"，重活一律放回主循环，否则 1ms 精度会被长中断破坏。

## 五、使用约定与已知边界

### Delay 模块

1. **调用顺序**：必须 `Timer1_Init()` 之后再调 `DelayMs()`，否则节拍不推进、程序卡死（已在 `Delay.h` 注释中标明）。
2. **最大延时**：参数为 `unsigned int`，上限 65535 ms（≈65.5 s）；更长请外层套循环或用 [2.3-1](#231-非阻塞软定时器最值得做的升级) 的检查式接口。
3. **回绕安全**：`(now - start)` 的无符号差值在 tick 溢出瞬间依然正确，原理见 [2.1](#21-差值法3-行核心代码为什么回绕也不怕)；但前提是**两次读取之间的间隔不超过一个回绕周期** —— tick 每 65.536 s 回绕一次，只要单次延时 ≤ 65535 ms，就始终成立。
4. **中断优先级**：节拍 ISR 务必短（只做重装 + 累加），否则 1ms 精度会被长中断破坏；需要重活请放到主循环。
5. **阻塞语义**：`DelayMs` 期间不响应任务切换；多任务场景请使用 [2.3-1](#231-非阻塞软定时器最值得做的升级) 的非阻塞方案。
6. **临界区**：读 16 位 `tick` 不是原子操作，读到一半被 ISR 打断会拼出错值（最坏偏差 256 ms 量级，而非 ±1ms）。防护应放在**取数函数内部**（`EA=0` 读完整再 `EA=1`，或"连读两次一致"法），见 [4.4](#44-寄存器速查timer1-模式-1)；应用层若需连续读多次 tick（如计算时间戳差）同理。`Delay.c` 的回绕差值算法本身无需额外保护 —— 只要读到的 tick 完整一致，差值法就自动正确。

### KEY 模块

7. **当前版本不含消抖**：`Key()` 是纯电平采样，机械按键直接使用会读到抖动造成的重复键值。请务必配合 [3.3-1](#331-加消抖最常用的第一个升级)（阻塞式）或 [3.3-4](#334-非阻塞定时扫描主循环不卡)（非阻塞式）处理。
8. **当前版本不含松手检测**：按住不放时，每调用一次 `Key()` 都会返回同一个键号，业务会被重复触发。需要"一次按下只响应一次"时，加边沿检测（[3.3-2](#332-边沿检测按一下只触发一次)）或在应用层 `while (Key() != 0);` 等松手。
9. **多键同按只报告一个**：优先级固定为 KEY4 > KEY3 > KEY2 > KEY1。需要真正识别组合键请改用位掩码（[3.3-6](#336-返回位掩码支持多键同按)）。
10. **依赖寄存器头文件中的 sbit 别名**：`P1_4` 等符号由 `<REGX51.H>` 提供。换用没有该别名的头文件（如某些 STC 官方头文件）时，需自行 `sbit KEY1 = P1^4;` 补定义。

### 组合使用

11. **消抖会引入模块依赖**：一旦把 `DelayMs()` 写进 `KEY.c`，KEY 模块就依赖 Delay → 依赖 Timer1，且 `Key()` 变为阻塞 20ms。想保持 KEY 的零依赖特性，请用非阻塞扫描方案。
12. **资源不冲突**：Delay 不占 I/O、KEY 不占定时器与中断，二者可同时使用，无资源竞争（见 [4.3](#43-片上资源占用总表)）。

## 六、贡献模板的规范（供后续新增模块参考）

- 一个模块一对 `.c/.h`，目录名沿用 `功能_外设或引脚_特性` 格式；
- `.h` 中写清**前置条件**（如"须先 Init"）与**资源占用**；
- **硬件绑定点必须收敛**：要么只出现在硬件配置层（如 Delay 只认 `Timer1_GetTick()` 一个函数名），要么集中在文件顶部连续的几行 `#define`（如 KEY 的 4 行引脚定义）；服务层其余代码不得出现寄存器名；
- 模块足够薄时（无初始化、无状态、十几行），允许服务层与硬件层合并，不必强行拆分 —— 判据是"改起来是否一目了然"，见 [第一章·4](#4-两种典型形态厚模块-vs-薄模块)；
- 每个模块附带一节"改哪里能得到什么"的移植 / 扩展说明（参照本文第二、三章）；
- 新增模块后，同步更新本文的**模块索引**、**目录结构**、**TL;DR 表**与 [4.2](#42-引脚占用总表) / [4.3](#43-片上资源占用总表) 两张资源表。
