# 51-MCU-Code-Template

这是一个用来存放 **51 单片机（STC89C52 / AT89S52 等 8051 内核）** 代码模板的仓库。

所有模板都遵循同一个目标：**把"能跑就行"的代码，拆成"换个工程就能直接套用"的模块**。

**每个模块的详细文档都放在各自目录的 `README.md` 里**（实现解析、移植指南、扩展路线、资源占用、使用边界）。本文件只做三件事：**模块索引**——仓库里有什么、各占什么资源，一张总表说清，避免新工程里撞车；**快速上手**——想干什么、去查哪一节；**写法约定**——贯穿所有模块的分层与命名规则，贡献新模块时照此对齐。

## 模块索引

| 模块 | 目录 | 对外接口 | 占用引脚 | 占用片上资源 | 依赖 | 详细文档 | 配套文章 |
|------|------|----------|----------|--------------|------|----------|----------|
| **Delay** | `Delay模块_Timer1节拍驱动_差值毫秒延时/` | `void DelayMs(unsigned int ms)` | **无** | Timer1 + ET1/EA + 约 5B RAM | 需自备 `Timer1.c/.h` | [README](./Delay模块_Timer1节拍驱动_差值毫秒延时/README.md) | [CSDN：差值法毫秒延时](https://blog.csdn.net/2503_93333717/article/details/170548684) |
| **KEY** | `KEY模块_P1.4~P1.7_按下为低/` | `unsigned char Key(void)` | **P1.4 ~ P1.7**（DIP40 第 5~8 脚） | 无定时器 / 无中断 / 约 1B RAM | 无（仅 `REGX51.H`） | [README](./KEY模块_P1.4~P1.7_按下为低/README.md) | [CSDN：独立按键扫描](https://blog.csdn.net/2503_93333717/article/details/170598453) |

两个模块**可以独立使用，也可以组合使用**（KEY 消抖正是靠 Delay 提供的毫秒节拍，见 [KEY README](./KEY模块_P1.4~P1.7_按下为低/README.md) 的「扩展路线 · 加消抖」）。

> **关于 Timer1**：Delay 模块的节拍源不在本仓库中，请使用你自己的定时器模块。
> 它只需对外提供两个接口：`Timer1_Init()`（启动 1ms 节拍）与 `Timer1_GetTick()`（读毫秒计数），
> 寄存器级配置见 [Delay README → 寄存器速查](./Delay模块_Timer1节拍驱动_差值毫秒延时/README.md)。
>
> **关于寄存器头文件**：`KEY.c` 用 `<REGX51.H>`，Delay 示例用 `<REGX52.H>`。二者都能编译通过
> （`REGX52.H` = `REGX51.H` + Timer2 寄存器），但同一工程内建议**统一成一个**，避免混用带来的困惑。

**硬件资源速记**

- **Delay**：Timer1（模式 1，16 位定时，中断号 3 / 向量 0x1B）+ ET1/EA + 约 5B RAM；**GPIO 占用为零**。
- **KEY**：P1.4~P1.7 共 4 个 I/O，**低电平 = 按下**；不占定时器、不占中断、约 1B RAM。
- 二者组合时：4 个按键脚 + Timer1 + ET1/EA + 约 6B RAM，演示 LED 另占 1 个 P2.x。
  8051 的 32 个 I/O 里除 KEY 占的 4 个、串口下载占的 P3.0/P3.1 之外，还有 26 个可用；
  Timer0、Timer2 以及串口以外的中断与优先级资源全部空闲，**两模块无资源竞争**。

| 项目 | 说明 |
|------|------|

## 一、写法约定（所有模块共同遵守）

### 1. 三层分工

| 层次 | 职责 | 本仓库示例 |
|------|------|-----------|
| 应用层 | 业务逻辑（点灯、菜单、游戏控制…） | `main.c`（由使用者自建） |
| 驱动 / 服务层 | 把硬件能力封装成纯软件接口 | `Delay.c`：`DelayMs(500)`<br>`KEY.c`：`Key()` → 键号 |
| 硬件配置层 | 寄存器级初始化与中断服务 | 你的 `Timer1.c`：`Timer1_Init()` + ISR |

模块之间**只通过 .h 中声明的函数通信**，绝不跨模块直接读写寄存器或共享全局变量。

### 2. 接口最小化

两个头文件加起来只有两行函数声明：

```c
void          DelayMs(unsigned int ms);   /* Delay.h：阻塞延时约 ms 毫秒 */
unsigned char Key(void);                  /* KEY.h：扫一次按键，返回 0~4 */
```

调用者不需要知道节拍从哪来、误差多大、按键接在哪个引脚、是高有效还是低有效 —— 这正是"可套用"的前提：**接口越窄，被替换 / 升级时波及的代码越少。**

### 3. 单向依赖

```text
                      ┌──> Delay（服务层）──> Timer1（硬件层）
应用层 main.c ────────┤        不回调            不认识 Delay
                      └──> KEY（服务层）───> P1.4~P1.7（直接寄存器）
                               不认识 Delay，也不认识 main
```

下层永远不知道上层的存在。因此 `Timer1` 可以同时喂给 Delay、按键消抖、PWM、串口超时等任意多个模块；`KEY` 也可以被任意业务调用，且**删掉 Delay 模块，KEY 照常工作**（只是失去消抖手段）。

### 4. 厚模块 vs 薄模块：允许合并层次

| | **Delay**（厚模块） | **KEY**（薄模块） |
|---|---|---|
| 是否依赖其他模块 | 是，依赖 Timer1 节拍 | 否，自给自足 |
| 是否操作寄存器 | **完全不操作**（纯算法） | 直接读 `P1_4~P1_7` |
| 硬件绑定点 | 收敛在 `Timer1_GetTick()` 这一个函数名 | 收敛在顶部 4 行 `#define` |
| 分层是否完整 | 服务层 / 硬件层严格分离 | 两层合并（模块太薄，分开反而累赘） |

`KEY.c` 同时扮演服务层和硬件层，按纯粹的分层原则它应该再拆一层（例如 `GPIO_ReadPort1()`）。但对于只有十几行、没有初始化、没有状态的模块，**强行拆层只会增加文件数量，不会增加可维护性**。判断标准是：*硬件绑定点是否收敛在一处、是否能一眼改完*。模块变厚（要加消抖、边沿检测、矩阵扫描）时，再把引脚读写下沉到独立的 GPIO 层也不迟 —— 详见 [KEY README 的扩展路线](./KEY模块_P1.4~P1.7_按下为低/README.md)。

## 二、两模块组合：一个典型 main.c

```c
#include <REGX52.H>
#include "Timer1.h"
#include "Delay.h"
#include "KEY.h"

sbit LED = P2^0;        /* 演示负载：LED 接 P2.0，可任意换到别的 P2/P1 位 */

void main()
{
    unsigned char key;

    Timer1_Init();          // 必须先启动节拍源，否则 DelayMs 永不返回
    while (1)
    {
        key = Key();        // 扫一次按键：0=无键，1~4=键号
        if (key != 0)
        {
            DelayMs(20);    // 消抖：跨过机械触点的抖动窗口
            if (Key() == key)   // 复查：20ms 后仍是同一个键才算真按下
            {
                LED = ~LED;         // 这里换成你的业务：切模式、调参数…
                while (Key() != 0); // 等松手，避免一次按下被重复计数
                DelayMs(20);        // 松手也抖，同样消抖一次
            }
        }
    }
}
```

> 这段代码演示的是**最朴素的阻塞式按键处理**，胜在直观。它会占用 CPU（`while(Key()!=0)` 期间主循环停摆），
> 若主循环还要刷数码管 / 跑串口，请改用非阻塞扫描，见 [Delay README 的 DelayCheck()](./Delay模块_Timer1节拍驱动_差值毫秒延时/README.md) 与 [KEY README 的非阻塞定时扫描](./KEY模块_P1.4~P1.7_按下为低/README.md)。

## 三、贡献模板的规范（供后续新增模块参考）

- 一个模块一个目录：一对 `.c/.h` **+ 一份模块级 `README.md`**（写清实现解析、移植指南、扩展路线、资源占用、使用边界，可参照现有两个模块的 README）；
- 目录名沿用 `功能_外设或引脚_特性` 格式；
- `.h` 中写清**前置条件**（如"须先 Init"）与**资源占用**；
- **硬件绑定点必须收敛**：要么只出现在硬件配置层（如 Delay 只认 `Timer1_GetTick()` 一个函数名），要么集中在文件顶部连续的几行 `#define`（如 KEY 的 4 行引脚定义）；服务层其余代码不得出现寄存器名；
- 模块足够薄时（无初始化、无状态、十几行），允许服务层与硬件层合并，不必强行拆分 —— 判据是"改起来是否一目了然"；
- 每个模块的 README 必须附带一节"改哪里能得到什么"的移植 / 扩展说明；
- 新增模块后，同步更新**本文件**的模块索引、目录结构、TL;DR 表与硬件资源速记。
