# LED模块_P0P2_低电平点亮

查表式 LED 图案显示模块（薄模块）：对外只暴露一个 `LED_SetPattern(pat)`，把"两个整口共 16 个 LED"的显示收敛成"一个编号 → 两个字节"的表。无初始化、无定时器、无中断；**新增图案只需在两张表里各加一个字节**，显示逻辑一个字都不用动。低电平点亮接法（写 0 = 亮，这不是随意约定，是 8051 的电流特性决定的，见第一节），换端口、改位序、改高电平点亮各有一步式改法（见移植指南）。

> 配套文章：[51单片机LED图案显示_P0P2双口查表驱动模块的设计与实现（CSDN）](https://blog.csdn.net/2503_93333717/article/details/170602400)

## 模块信息

| 项目 | 说明 |
|------|------|
| 对外接口 | `void LED_SetPattern(unsigned char pat)` —— 显示编号 `pat` 对应的图案；`pat` 越界时回退为全灭 |
| 占用引脚 | **P0.0 ~ P0.7 + P2.0 ~ P2.7** 整两个口共 16 个 I/O（DIP40 第 32~39 脚、第 21~28 脚） |
| 占用片上资源 | 无定时器 / 无中断 / 两张图案表约 12B ROM（`code` 区）/ RAM 约 1B（形参，通常直接落在寄存器里） |
| 依赖 | 无（仅 `REGX51.H`） |
| 初始化 | **不需要**：复位后端口锁存器全为 1，接好上拉的 P0 上电即"全灭"（安全默认态） |
| 点亮约定 | **低电平点亮**：往口上写 0 = 亮，写 1 = 灭（物理原因见 1.2 节） |

配套模块：[KEY模块_P1.4~P1.7_按下为低](../KEY模块_P1.4~P1.7_按下为低/README.md) —— 按键切图案是三模块联动的最小示范（见扩展路线 4.4）；[Delay模块_Timer1节拍驱动_差值毫秒延时](../Delay模块_Timer1节拍驱动_差值毫秒延时/README.md) —— 流水灯 / 闪烁的节奏来源（见扩展路线 4.3）。两个依赖都可以不引入，本模块照样独立工作。

## 一、接线与点亮原理

### 1.1 板面布局与引脚

16 个 LED 排成两列：左列 D2~D9 由 P0 驱动，右列 D10~D17 由 P2 驱动，两列的位序方向一致（**P0.0 / P2.0 都是最上面那颗**）：

```text
              左列（P0 驱动）      右列（P2 驱动）
最上一排        D9  ← P0.0          D10 ← P2.0
              D8  ← P0.1          D11 ← P2.1
              D7  ← P0.2          D12 ← P2.2
              D6  ← P0.3          D13 ← P2.3
              D5  ← P0.4          D14 ← P2.4
              D4  ← P0.5          D15 ← P2.5
              D3  ← P0.6          D16 ← P2.6
最下一排        D2  ← P0.7          D17 ← P2.7
```

同一行两颗 LED 的编号之和恰好都是 19（D9+D10、D8+D11、…、D2+D17），模块里的图案 A / B 正是按这个棋盘格设计的：A 亮"左列奇数排 + 右列偶数排"，B 亮剩下的一半，两者互为补集 —— 来回切换就是整板闪烁。

| 端口 | 引脚 | DIP40 脚号 | 接法 |
|------|------|-----------|------|
| P0.0~P0.7 | 8 个 | 第 39~32 脚 | 每脚 → 限流电阻 → LED 阴极；LED 阳极接 VCC |
| P2.0~P2.7 | 8 个 | 第 21~28 脚 | 同上 |

### 1.2 电路：为什么是"低电平点亮"

每颗 LED 的接法：**VCC → LED 阳极；LED 阴极 → 限流电阻（330Ω~1kΩ）→ I/O 引脚**。引脚写 0 时电流从 VCC 经 LED 流进引脚（灌电流），LED 点亮；写 1 时两端无压差，熄灭。

"低电平点亮"不是习惯问题，是 **8051 的电流特性**决定的：

- 51 的准双向口**灌电流能力强**（往引脚里灌电流、拉到地，单脚可达约 10mA 量级），点 LED 又亮又稳；
- **拉电流能力弱**（输出 1 靠内部弱上拉，只有几百 µA），如果反过来"引脚接阳极、GND 接阴极"，LED 会非常暗甚至不亮。

所以 51 平台上点灯的通用姿势就是：阳极接 VCC、引脚吃灌电流、**写 0 点亮**。目录名里的"低电平点亮"说的就是这件事。

**P0 的经典大坑**：P0 口与其他口不同，是**开漏输出、没有内部上拉**。写 1 时引脚是高阻悬空态，LED 不会可靠熄灭（可能微亮、闪烁、随干扰乱变）。因此：

1. **用 P0 点灯必须外接 4.7k~10k 上拉排阻**（教材实验板通常已焊好 8 位排阻）；
2. 接了上拉之后，上电复位（锁存器全 1）就是确定的"全灭"状态，与本模块"复位即安全"的设计刚好咬合；
3. 每颗 LED 必须串限流电阻。按红 LED Vf≈2V 估算：330Ω ≈ 9mA/颗，470Ω ≈ 6mA/颗，1kΩ ≈ 3mA/颗。全亮 16 颗时合计几十 mA，注意单脚灌电流按 ≤10mA 预算、整机别超供电能力。

## 二、源码解析

### LED.h（全文）

```c
#ifndef __LED_H__
#define __LED_H__

/* 图案编号（对应图1布局，低电平点亮） */
enum {
    LED_PAT_OFF = 0,   /* 全灭 */
    LED_PAT_ON,        /* 全亮 */
    LED_PAT_A,         /* 组A：D9 D7 D5 D3 / D11 D13 D15 D17 */
    LED_PAT_B,         /* 组B：D8 D6 D4 D2 / D10 D12 D14 D16 */
    LED_PAT_LEFT,      /* 左列：D2~D9（P0） */
    LED_PAT_RIGHT,     /* 右列：D10~D17（P2） */
    LED_PAT_NUM
};

void LED_SetPattern(unsigned char pat);   /* 显示指定图案 */

#endif
```

头文件暴露两样东西：**图案编号枚举**（应用层用 `LED_PAT_A` 这种带语义的名字，而不是裸的 2、3）和**一个显示函数**。`LED_PAT_NUM` 放在枚举末尾，天然等于图案总数 —— 表长度、越界判断、应用层循环取模全都引用同一个常量，加图案时不会漏改。

### LED.c（全文）

```c
#include "LED.h"
#include <REGX51.H>

/* ---------- 硬件映射（图1，LED 低电平点亮） ----------
 * P0.0~P0.7 -> D9  D8  D7  D6  D5  D4  D3  D2（自上而下）
 * P2.0~P2.7 -> D10 D11 D12 D13 D14 D15 D16 D17（自上而下）
 * 新增图案只需在两张表里各加一个字节，不用再写函数。
 *-----------------------------------------------------*/

static code unsigned char PAT_P0[LED_PAT_NUM] = {
    0xFF,   /* OFF 全灭 */
    0x00,   /* ON  全亮 */
    0xAA,   /* A：P0.0/2/4/6 拉 low 亮 D9 D7 D5 D3 */
    0x55,   /* B：P0.1/3/5/7 拉 low 亮 D8 D6 D4 D2 */
    0x00,   /* 左列全亮 */
    0xFF    /* 右列：P0 全灭 */
};

static code unsigned char PAT_P2[LED_PAT_NUM] = {
    0xFF,   /* OFF 全灭 */
    0x00,   /* ON  全亮 */
    0x55,   /* A：P2.1/3/5/7 拉 low 亮 D11 D13 D15 D17 */
    0xAA,   /* B：P2.0/2/4/6 拉 low 亮 D10 D12 D14 D16 */
    0xFF,   /* 左列：P2 全灭 */
    0x00    /* 右列全亮 */
};

void LED_SetPattern(unsigned char pat)
{
    if (pat >= LED_PAT_NUM) pat = LED_PAT_OFF;   /* 越界保护 */
    P0 = PAT_P0[pat];
    P2 = PAT_P2[pat];
}
```

去掉两张表，函数体只剩 4 行：一个越界保护 + 两次整口赋值。四个设计点值得展开。

**① 硬件绑定点收敛在"两张表 + 两行赋值"。** 全文件只有 `P0 = ...` 和 `P2 = ...` 两处碰硬件。想换端口？只改这两行（顺带改一下注释），下面所有图案数据一个字都不用动。

**② `code` 关键字：图案表放进 ROM。** `static code unsigned char` 表示"本文件私有、存 Flash、运行期只读"，12 个图案字节完全不占 RAM；SDCC 写作 `__code`（见移植指南步骤 6）。表在 ROM 里改不了，恰好逼出"固定图案走数据表、动态效果走另外接口"的清晰分工（扩展路线 4.2）。

**③ 查表法：新增图案从"改代码"变成"改数据"。** 显示逻辑永远是"把两张表的第 `pat` 项各写一个口"，图案本身只是数据。加一种图案 = 两张表各加一个字节 + 枚举里加一个名字，函数一行不动 —— 这就是数据驱动的价值：改动面小，也不会把显示逻辑改坏。

**④ 越界保护：错参兜底成全灭。** `if (pat >= LED_PAT_NUM) pat = LED_PAT_OFF;` 让任何非法编号都落到最安全、最不刺眼的状态，而不是把表外的未知数据写到端口上（越界读数组属于未定义行为）。代价是"静默"：传错了不会报错，调试期可临时把兜底改成死循环便于定位（见使用边界第 5 条）。

## 三、移植指南（怎么修改一下就能套用）

以下假设你新建了一个 Keil C51 工程，想把本模块搬进去。

### 步骤 1：拷文件

把 `LED.c/.h` 拖进工程，加一下 Include Paths（`Options for Target → C51 → Include Paths`），**完事**。不需要初始化函数、不占定时器、不开中断。硬件侧只需确认两件事：P0 的上拉排阻在场、每颗 LED 串了限流电阻（见 1.2 节）。

### 步骤 2：换端口 —— 只动两张表名和两行赋值

全文件与端口名相关的只有：顶部注释、`PAT_P0` / `PAT_P2` 两个表名、函数里 `P0 = / P2 =` 两行。比如整板换到 P1 / P3（把 P0 留给数码管、P2 留给别的）：

```c
static code unsigned char PAT_P1[LED_PAT_NUM] = { ... };   /* 表名里的 P0 改成 P1，数据不动 */
static code unsigned char PAT_P3[LED_PAT_NUM] = { ... };

void LED_SetPattern(unsigned char pat)
{
    if (pat >= LED_PAT_NUM) pat = LED_PAT_OFF;
    P1 = PAT_P1[pat];      /* 端口名与表名对上即可 */
    P3 = PAT_P3[pat];
}
```

**选口提示**：

- P3.0 / P3.1 是串口下载脚，别选；
- P1.0 / P1.1 复用 Timer2 的 T2 / T2EX，工程里用了 Timer2 要避开；
- P0 继续当输出口用没问题，但**上拉排阻不能省**；
- 换到 STC12 / STC15 / STC8 系列：上电默认准双向口通常可直接用，但若工程把端口改成了推挽 / 开漏模式，写 0 / 写 1 的表现会变，需核对端口模式寄存器（本模板针对 89 系列，无端口模式寄存器）。

### 步骤 3：位序对不上 —— 重排表字节，逻辑不动

表是"按位排列的字节"：每个字节的 bit n 对应本列自上而下第 n+1 颗 LED。如果你的板子位序相反（bit0 在最下）或两列位置互换，只需把每个表字节的位序照板子重排。以棋盘格为例：位序上下镜像后 `0xAA ↔ 0x55`、`0x55 ↔ 0xAA`，图案名与含义仍由应用层解释。

核对方法：先只写 `0x01`（本列只亮 bit0 那颗），确认它在你板子上是哪颗、排在第几位，其余依次类推，一次就能把整张表的位序校准。

### 步骤 4：改"高电平点亮" —— 全表取反

若你的电路是引脚 → 电阻 → LED 阳极、阴极接 GND（写 1 亮，常见于灌电流不出来的场合），有两种改法：

- **改数据（推荐）**：把两张表里每个字节按位取反（`0xFF ↔ 0x00`、`0xAA ↔ 0x55`…），"表里就是往口上写的值"的语义不变；
- **改代码**：函数里写成 `P0 = ~PAT_P0[pat]; P2 = ~PAT_P2[pat];`，表一个字节不动。

顺手把目录名和注释里的"低电平点亮"改成"高电平点亮"，保持命名规则的一致性。

### 步骤 5：增删 LED 与图案

- **少用一个口**（只留 8 颗）：删掉 `PAT_P0` 表和 `P0 = ...` 那行，模块变 8 灯版；
- **加图案**：`enum` 里在 `LED_PAT_NUM` **之前**插入新名字，两张表在**相同下标位置**各加一个字节；
- **加到 24 颗**：再加一张表 + 一行赋值即可，接口不变。

⚠️ 两张表是"按下标一一对应"的：第 `pat` 个图案 = `PAT_P0[pat]` 与 `PAT_P2[pat]` 组合。往中间插图案时，两张表必须插在**同一位置**，否则亮出来的是"左半张新图 + 右半张旧图"。

### 步骤 6：换编译器

Keil C51 的 `code` 在 SDCC 写作 `__code`（部分型号亦作 `__flash`）。函数体没有任何 `sbit / sfr / interrupt` 依赖，除这一个关键字外可原样编译。

## 四、扩展路线（改哪里能得到什么）

每一节给出"改哪里 → 得到什么"。

### 4.1 新增图案（最常用的第一个升级：不改函数，只加数据）

以"四角亮"（D9、D2、D10、D17）为例 —— D9 = P0.0、D2 = P0.7 → P0 应写 `0x7E`；D10 = P2.0、D17 = P2.7 → P2 应写 `0x7E`：

```c
enum {
    LED_PAT_OFF = 0,
    LED_PAT_ON,
    LED_PAT_A,
    LED_PAT_B,
    LED_PAT_LEFT,
    LED_PAT_RIGHT,
    LED_PAT_CORNER,    /* 四角亮：D9 D2 D10 D17 ← 新增 */
    LED_PAT_NUM
};

static code unsigned char PAT_P0[LED_PAT_NUM] = {
    0xFF, 0x00, 0xAA, 0x55, 0x00, 0xFF,
    0x7E    /* CORNER：bit0、bit7 拉 low */
};
static code unsigned char PAT_P2[LED_PAT_NUM] = {
    0xFF, 0x00, 0x55, 0xAA, 0xFF, 0x00,
    0x7E    /* 与 PAT_P0 同下标 */
};
```

应用层从此多了一个可以调的名字：`LED_SetPattern(LED_PAT_CORNER);`。**位值的算法**：想亮哪几颗，就把它们对应的位清 0（低电平点亮），其余保持 1 —— 例如左列中间四颗（D6~D3 = P0.3~P0.6）是 `0x87`。

### 4.2 加"逃生舱口"接口：任意字节显示，流水灯立刻能做

图案表适合"有限个固定画面"；想跑流水灯、跑马灯这类**连续变化**的效果，给模块加一个最薄的逃生舱口（原有接口一个字不动，向后兼容）：

```c
/* LED.h 追加 */
void LED_SetBytes(unsigned char p0, unsigned char p2);   /* 直接指定两个口的原始字节 */

/* LED.c 追加 */
void LED_SetBytes(unsigned char p0, unsigned char p2)
{
    P0 = p0;
    P2 = p2;
}
```

左列自上而下流水一圈、再右列一圈（`DelayMs` 来自 [Delay 模块](../Delay模块_Timer1节拍驱动_差值毫秒延时/README.md)）：

```c
unsigned char i;
while (1)
{
    for (i = 0; i < 8; i++) {                    /* 左列：P0.0→P0.7 = D9→D2 */
        LED_SetBytes((unsigned char)~(0x01 << i), 0xFF);
        DelayMs(150);
    }
    for (i = 0; i < 8; i++) {                    /* 右列：P2.0→P2.7 = D10→D17 */
        LED_SetBytes(0xFF, (unsigned char)~(0x01 << i));
        DelayMs(150);
    }
}
```

分工变清晰了：**枚举图案接口负责"语义画面"，字节接口负责"动态效果"**，两者共存互不干扰 —— 这也是模块接口演进的通用姿势：加新能力时先加新函数，别动旧接口。

### 4.3 闪烁 / 非阻塞 / 呼吸灯

**整板闪烁**：图案 A 与 B 恰好互补，两张表天生就是为此设计的：

```c
while (1)
{
    LED_SetPattern(LED_PAT_A);
    DelayMs(300);
    LED_SetPattern(LED_PAT_B);
    DelayMs(300);
}
```

**非阻塞闪烁**（主循环不卡；需先按 [Delay README 的扩展路线](../Delay模块_Timer1节拍驱动_差值毫秒延时/README.md) 给 `Delay.c` 加 `DelayCheck()`）：

```c
unsigned int t  = Timer1_GetTick();
unsigned char a = 1;

while (1)
{
    if (DelayCheck(t, 300))              /* 每 300ms 翻一次面 */
    {
        t = Timer1_GetTick();
        LED_SetPattern(a ? LED_PAT_A : LED_PAT_B);
        a = !a;
    }
    /* 300ms 的空档里 CPU 可以扫按键、跑别的任务 —— 主循环不停摆 */
}
```

**呼吸灯**：本质是 PWM。粗糙版可基于 1ms 节拍做 20 级软件 PWM（周期 20ms，16 颗一起呼吸；想只呼吸一个口，另一个参数固定传 0xFF）：

```c
/* 软件呼吸灯：周期 20ms、20 级亮度，吃 Delay 模块的 1ms 节拍 */
unsigned char duty = 0, dir = 1, i;

while (1)
{
    for (i = 0; i < 20; i++)                   /* 一个 PWM 周期 = 20ms */
    {
        LED_SetBytes(i < duty ? 0x00 : 0xFF,    /* 亮的时间片写 0，其余写 1 */
                     i < duty ? 0x00 : 0xFF);
        DelayMs(1);                             /* 每个时间片停 1ms */
    }

    if (dir) { duty++; if (duty >= 20) dir = 0; }      /* 渐亮到顶 */
    else     { if (duty == 0) dir = 1; else duty--; }  /* 渐暗到底 */
}
```

想平滑、想省 CPU，就上定时器中断做 PWM —— 注意 Timer1 已被 Delay 占用，**呼吸灯建议用 Timer0**（目录名建议 `PWM模块_Timer0_多路呼吸灯`，后续再收进仓库）。

### 4.4 与按键联动：KEY 输入 + LED 输出

三模块联动的最小示范（完整可跑版本见仓库根 README「模块组合」）：

```c
unsigned char pat = LED_PAT_ON;
LED_SetPattern(pat);

while (1)
{
    unsigned char key = Key();
    if (key != 0)
    {
        DelayMs(20);                       /* 消抖 */
        if (Key() == key)
        {
            pat = (unsigned char)((pat + 1) % LED_PAT_NUM);   /* 循环切图案 */
            LED_SetPattern(pat);
            while (Key() != 0);            /* 等松手 */
            DelayMs(20);                   /* 松手也抖，同样消抖一次 */
        }
    }
}
```

`Key()` 返回 1~4、`LED_SetPattern()` 吃 0~5，`main` 只做一层薄薄的翻译（加一取模）。两个模块互相不认识，业务怎么组合都行 —— 想要"4 个键直接选 4 个图案"，一行 `LED_SetPattern(key - 1);` 就够。

### 4.5 端口让位：与数码管、点阵共存

P0 / P2 是 51 上最抢手的两个口（数码管的经典接法就是 P0 段选 + P2 位选）。LED 模块整口占用了它们，共存思路按代价从低到高：

1. **LED 缩口**：按移植指南步骤 5 删掉一个口的表，8 颗 LED 让出整 8 个脚；
2. **换口**：按步骤 2 把 LED 挪到相对空闲的口（注意 P3.0/P3.1 下载脚、Timer2 复用脚、P0 上拉）；
3. **分时复用**：在数码管扫描的间隙里偶尔刷新一次 LED 图案 —— 显示类外设变化率低，通常可行，但需要 74HC573 之类的锁存器把两个口的数据"钉住"，属于进阶改造，做之前先想清楚。

原则就一句：**模块占用的资源越少、绑定点越收敛，越容易和别人共存**。这也是本仓库把"资源占用"写进每个模块 README 的原因。

### 4.6 逐位修补：改一颗灯，别整口重画

想在"当前画面"上只点 / 灭某一颗（比如把 D5 单独打开做提示灯），加一个带影子寄存器的逐位接口：

```c
/* LED.h 追加 */
void LED_SetBit(unsigned char idx, unsigned char on);
/* idx 0~7 = 左列 D9~D2（P0.0~P0.7），8~15 = 右列 D10~D17（P2.0~P2.7）；on 非 0 点亮 */

/* LED.c 追加 */
static unsigned char shadowP0 = 0xFF;    /* 影子寄存器：1=灭 0=亮，与端口约定一致 */
static unsigned char shadowP2 = 0xFF;

void LED_SetBit(unsigned char idx, unsigned char on)
{
    unsigned char mask = (unsigned char)(0x01 << (idx & 0x07));   /* 组内位号 */

    if (idx < 8) {
        if (on) shadowP0 &= (unsigned char)~mask; else shadowP0 |= mask;
        P0 = shadowP0;
    } else {
        if (on) shadowP2 &= (unsigned char)~mask; else shadowP2 |= mask;
        P2 = shadowP2;
    }
}
```

两个要点：

- **为什么维护影子变量而不是直接 `P0 &= ~mask`**：对端口直接做读-改-写，读到的可能是引脚电平而非锁存器值，还容易把 `LED_SetPattern` 刚写的整口状态改花。先在影子变量上改、再整口写回，状态永远由自己持有，显示不会漂移；
- **注意混用**：`LED_SetBit` 与 `LED_SetPattern` / `LED_SetBytes` 各写各的，后两者一次整口写会绕过影子变量。要么别混用，要么给它们各补两行 `shadowP0 = p0; shadowP2 = p2;`，让所有出口都过同一份状态。

## 五、资源占用

| 资源 | 占用情况 |
|------|----------|
| I/O | **P0.0~P0.7**（DIP40 第 39~32 脚）+ **P2.0~P2.7**（第 21~28 脚）共 16 个，**低电平点亮**，P0 需外接 4.7k~10k 上拉排阻 |
| 定时器 | **不占用** |
| 中断 | **不占用** |
| RAM | 约 1B（形参 / 局部变量，通常直接落在寄存器里）；用 4.6 逐位接口再加 2B 影子变量 |
| ROM / Flash | 两张图案表共 12B（`code` 区，随图案数线性增长）+ 十几条指令 |
| 特殊功能寄存器 | P0（0x80）、P2（0xA0），**整口写**；不读引脚、不碰其他寄存器 |
| 电流 | 单颗 3~9mA（330Ω~1kΩ 限流）；16 颗全亮合计约 50~150mA，注意单脚灌电流与整机供电能力 |

与 [Delay](../Delay模块_Timer1节拍驱动_差值毫秒延时/README.md)、[KEY](../KEY模块_P1.4~P1.7_按下为低/README.md) 同时使用：16 + 4 = 20 个 I/O + Timer1 + ET1/EA + 约 8B RAM，无资源竞争；但 P0 / P2 已被整口占用，数码管 / 点阵类模块需要让位（见 4.5）。

## 六、使用边界（防坑清单）

1. **P0 必须外接上拉排阻**：开漏输出没有内部上拉，写 1 时引脚悬空，"熄灭"不可靠（微亮、闪烁、随干扰变）。上电"复位即全灭"的确定状态，前提也是上拉在场。
2. **低电平点亮固化在表数据里**：电路改成高电平点亮时，必须按移植指南步骤 4 同步改表（或取反输出），否则整幅画面全部反相。
3. **整口独占 P0 / P2**：这两个口不能再接数码管段 / 位选、点阵、外部总线等其他外设，要共存先做 4.5 的端口让位。
4. **限流电阻不能省**：单颗按 3~9mA 设计（330Ω~1kΩ）；不串电阻直点会瞬间超出灌电流能力，伤 LED 更伤端口。
5. **越界保护是静默的**：`LED_SetPattern(99)` 不会报错，只会显示全灭。安全优先，但调试期建议临时把兜底改成 `while (1);` 卡死定位，正式版再改回。
6. **图案表在 ROM 里运行期只读**：想动态改变显示，请用 4.2 的 `LED_SetBytes`（或 4.6 的影子寄存器），别指望改表。
7. **两张表下标必须对齐**：任何增删图案的操作，`PAT_P0` 与 `PAT_P2` 必须同步插在相同位置，否则左右半张图错位（见移植指南步骤 5 的警告）。

> **模块定位**：这是仓库里第一个"纯输出"型薄模块，和 KEY 恰好是一对 —— KEY 把"引脚电平"翻译成"业务编号"，LED 把"业务编号"翻译成"端口画面"。中间那层业务逻辑，才是应用层自己该写的东西。
